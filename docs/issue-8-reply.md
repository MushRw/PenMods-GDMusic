感谢实现，两个方向都给全了。我们的 GD 音乐插件已用「方向 1（QML context property）」真机接入（YDP02X），下拉面板的曲目/歌词/进度/四个控制按钮/`end()` 回落宿主全部正常，替代了此前直接调用宿主内部符号的方案。

落地过程中有两条实测反馈，供参考：

**1. `MediaSession::end()` 没有属主校验。**

被接管的旧持有者收到 `sessionRevoked` 后，如果按直觉调 `end()`，会把**新属主**的会话一起关掉（新属主的卡片随之消失）。我们在 `sessionRevoked` 处理里只能刻意不调 `end()` 来绕开。建议 `end()` 对「非当前属主」的调用直接 no-op（或文档写明"被接管方不应调 end"）。

**2. 停播即 `end()` 会让面板入口整体消失，插件只能靠"保留期"绕开。**

面板卡片可见性 = `mediaSession.active`，所以一旦 `end()`，卡片（连同续播入口）就没了，用户想从面板一键续播只能重新打开插件。我们的绕法是：停播时只置 `playState=Stopped`、保留会话（自己起一个 3 分钟定时器，超时才真正 `end()`）。这套"保留期"逻辑放在插件侧多少有点别扭，若面板能对 `Stopped` 状态的会话也保留卡片（或文档说明这个取舍），插件就不用各写各的绕法。

另外补充一条对 `doc/PLUGIN_DEV_GUIDE.md` 可能有用的小经验：插件页由 `YDynamicPageStack`（无缓存版本）装载，`backButtonClicked` 后页面会被销毁——媒体会话和 `Connections{target: mediaSession}` 必须挂在**比页面活得久**的对象上（我们用了 QML singleton）。文档里若提一句，能帮后来者少踩一个坑。
